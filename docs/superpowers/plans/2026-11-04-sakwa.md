# Sakwa Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans in this session, task by task.

**Goal:** Deliver the approved native, portable three-context notes mod.
**Architecture:** Pure context and journal modules, an injected atomic file adapter,
and a retained GPUI textarea. An append-only snapshot journal is the source of
truth: every edit is an immutable, uniquely named record. Concurrent edits form
branches instead of overwriting text. All notes and history are derived from it.
**Tech Stack:** JavaScript ES modules, native Herdr GPUI, Node built-in tests.
**Spec:** docs/design.md

## Global Constraints

- One plain-text note per tab, per space, and per local installation globally.
- Preserve text and corrupt originals; missing contexts never cause deletion.
- Portable runtime APIs only. Do not push or alter the active layout.
- Commit each stage; native check required; platform claims bounded by evidence.

## Review Focus

- Concurrent editors: retain both branches and allow explicit recovery.
- Failed/unfinished writes: retain draft in per-copy localStorage and retry.
- Context switches and delayed reads: never assign text to a different note.
- Remote machine disconnects: unavailable is not archived.
- Recipients disappearing or transport size rejection: never clear/truncate text.

## Execution decisions

- Work in requested checkout on feat/sakwa-notes; no copied layout or extra checkout.
- Immutable snapshot journal replaces mutable note files: atomic creation with
  expected=null cannot silently clobber text; failed writes can be retried.
- Recovery history is never automatically pruned in v1.
